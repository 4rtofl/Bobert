# LLM利用コスト

最終更新: 2026-11-22

## 方針

- LLMの利用料は、使ったユーザー本人が自分の分を負担する。Botの運営者は負担しない。
- 返答などのAIの呼び出しは、sigw([4rtofl/si-gateway](https://github.com/4rtofl/si-gateway))を通す。Bobertを使うのはsigwのメンバーだけで、費用はsigwが1人ずつ記録し、毎月まとめて精算する(「AIの呼び出しと費用の負担」を参照)。
- 例外として、会話の検索(RAG)のための埋め込みの費用は運営者が負担する。Cloudflare Workers AIを使い、少額で済む(bge-m3なら100万トークンあたり約$0.012)。
- 音声メッセージを文字にする費用も、運営者が負担する。埋め込みと同じくWorkers AIを使い、少額で済む(1分あたり約$0.0005。「音声メッセージの費用」を参照)。
- 知識チャンネルのファイルを文字にする費用(Workers AIのMarkdown変換と、PowerPointをPDFにするコンテナ)も、運営者が負担する。多くの形式の変換は無料で、コンテナも月250回ほどまでは、Workersの有料プランに含まれる分で収まる。要約の費用は、ファイルを送った人の負担(「知識チャンネルの費用」を参照)。
- クレジットの寄付は、いまは使わない(「クレジットの寄付」を参照)。
- 返答のためにキーを登録する必要はない。エージェントと動画の作成も、sigwを通して呼ぶので、キーの登録は要らない(「エージェントの費用」と「動画の作成の費用」を参照)。
- サブスクリプションの利用枠(Claude Pro/Max、ChatGPT、Google AI Pro/Ultra、GitHub Copilotなど)は使わない。
- 例: AさんとBotの会話にBさんが返信した場合、その返信への応答の費用はBさんが払う。
- 会話の履歴や検索結果に他の人の発言が含まれる場合も、そのまま文脈として、sigwを通してプロバイダ(AnthropicかOpenRouter)に送る。個別の告知はしない。上の例では、Aさんの発言も、Bさんへの応答のために送られる。
- Bot側では使用量の上限を設けない。上限額は、sigwのキーに設定できる。sigwが断ったときは(上限額に達したときなど)、sigwが返した理由を、返答で伝える。
- 右クリックメニューの「Jevに聞く」と`/jev`で呼ぶJev(TypeSafeの判定モデル)の費用も、使った本人が、本人のTypeSafeのキーで払う(「Jevの費用」を参照)。

## AIの呼び出しと費用の負担

- **通り道:** メンションへの返答、「Bobertに聞く」、要約(自動と今すぐ)、記憶のまとめ、知識チャンネルのファイルの要約、Web検索、モデル情報(「その他」で入力したClaudeの確認など)、エージェントと動画の作成(Managed Agents)は、sigwを通して呼ぶ。Bobertは、sigwのWorkerをService Binding(`SIGW`。入口は`BobertGateway`)で呼ぶ。
  - Anthropicは`https://sigw/anthropic/v1/messages`のように、OpenRouterは`https://sigw/openrouter/api/v1/chat/completions`のように、sigwの中継のパスで呼ぶ。Service Bindingなので、ホスト名は使われない。
  - AnthropicのSDKは、送り先(`baseURL`)と`fetch`を差し替えて使う。
  - OpenRouterのモデル一覧は、キーがなくても読めるので、sigwを通さずに直接取る。
- **キー:** Bobert用のsigwのキーを、Workerのシークレットに置く。Anthropic用が`SIGW_ANTHROPIC_KEY`、OpenRouter用が`SIGW_OPENROUTER_KEY`。Anthropicには`x-api-key`、OpenRouterには`Authorization: Bearer`で、sigwのキーだけを送る。Anthropicのキーはsigwの専用のワークスペースのものなので、ワークスペースのIDは送らない。
- **費用を払う人:** 返答を頼んだ人(メンションや返信をした人、ボタンやメニューを押した人)。呼び出しのたびに、その人のDiscordのIDを`x-sigw-user`ヘッダーで送る。sigwはこのIDごとに使った額を記録し、毎月まとめて精算する(Daichoo)。
  - 記憶のまとめは記憶の持ち主、知識チャンネルのファイルの要約はファイルを送った人が払う。
  - モデル情報の取得は無料だが、同じく頼んだ人のIDを送る。
  - エージェントはチャンネルの持ち主、動画の作成は動画を頼んだ人が払う。
- **使えるモデル:** Bobertにあるsigwのキーで決まり、全員で同じ。両方のキーがあれば、Claudeの候補はAnthropicで直接呼び、ほかはOpenRouterで呼ぶ。`SIGW_ANTHROPIC_KEY`が空ならClaudeもOpenRouter経由で呼び、`SIGW_OPENROUTER_KEY`が空ならClaude以外は使えない。
- **断られたとき:** sigw自身が断ったときは、プロバイダと同じ形のエラーで、文が「[sigw]」で始まる。この文は送った内容を含まないので、返答で、そのまま理由として見せる(例:「[sigw] sigw キーの今月の上限額に達しました」)。プロバイダが断ったときは、今までどおり、エラーの種類から理由を書く。

## 対応する資格情報

返答も、エージェントと動画の作成もsigwを通すので、下のAnthropicとOpenRouterのキーは、もう呼び出しには使わない。登録の仕組みは、別に見直す(#128)。

| 方式              | 登録方法                                                                     | 課金先                         | 使えるモデル                                                |
| ----------------- | ---------------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------- |
| Anthropic APIキー | ユーザーがClaude Consoleで発行したキーを登録する                             | ユーザーのClaude Console組織   | Claudeの各モデル                                            |
| OpenRouter        | OAuth(PKCE)でユーザーがOpenRouter上でBotを承認し、本人のキーを発行してもらう | ユーザーのOpenRouterクレジット | OpenRouterで提供される各社のモデル(GPT、Gemini、Claudeなど) |
| TypeSafe APIキー  | ユーザーがTypeSafeのコンソールで発行したキーを登録する                       | ユーザーのTypeSafeの組織       | Jevだけ(「Jevに聞く」で使う。AIの返答には使わない)          |
- Anthropicに直接対応する理由: Claude Max/Teamの契約者は、プラン付属の月額APIクレジットを、紐付けたConsole組織のAPIキーで使える。月額はMax 5xが$100、Max 20xが$200、Teamが最大$500。
- OpenRouterのモデル単価は各社と同額。クレジット購入時に手数料がかかる(約5.5%、最低$0.80。2026-10時点の第三者による解説)。
- OpenRouterへのリクエストには、データを保存・学習しないプロバイダだけを使う指定(`provider.data_collection: "deny"`)を付ける。会話には他の人の発言も含まれるため。この指定により、使えなくなるモデルもある。

## 資格情報の登録・保存・削除

- **Anthropic:** `/setup`のボタンでモーダルを開き、APIキーを入力してもらう。
  - キーがワークスペースに属さない場合(Claude Consoleで、ワークスペースを指定せずに作った個人キーなど)は、使うワークスペースのID(`wrkspc_`で始まる)も入力してもらう。リクエストのたびに`anthropic-workspace-id`ヘッダーで送る。IDは秘密の情報ではないので、暗号化せずに保存する。
  - ワークスペースIDが足りないとき、IDが正しくないときは、確認の結果でその理由を表示する。
  - 入力は、全角の英数字を半角にし、空白と見えない文字を取り除いてから使う。
- **OpenRouter:** `/setup`で連携用のリンクを送り、OAuth(PKCE)で連携する。コールバックはWorkerで受ける。
  - リンクは`/setup`を実行した本人にだけ見える形で送り、10分間だけ有効にする(OpenRouterのcodeの有効期間に合わせる)。1回使うと無効になる。
  - リンクに付ける`state`で、どのDiscordユーザーのキーとして保存するかを決める。
  - OpenRouterに作られるキーの名前に、Discordのユーザー名を入れる(例: `Bobert (Discord: alice)`)。承認の画面で、どのアカウントと連携するのかを確かめられるようにするため。
  - 連携が済んだら、`/setup`への追加の返信で、本人にメンションして「OpenRouterとの連携が完了しました。」と知らせる。`/setup`の返信と同じく、本人にだけ見える形にする。そのために、`/setup`のInteractionのトークン(15分有効)を`state`と一緒に保存しておく。
- **TypeSafe(「Jevに聞く」と`/jev`):** `/setup`の「TypeSafeのキーを登録」ボタンでモーダルを開き、APIキーを入力してもらう。キーは[TypeSafeのコンソール](https://console.typesafe.ai/keys)で発行する。
  - `/setup`の画面では、OpenRouterの行の次に「- TypeSafe: 未登録」(または「登録済み」)と書き、最後に「-# TypeSafeのキーは、右クリックメニューの「Jevに聞く」と `/jev` で使います。」と添える。ボタンは「TypeSafeのキーを登録」(登録済みなら「TypeSafeのキーを登録し直す」)。
  - モーダルは、タイトル「TypeSafeのAPIキーの登録」、入力欄「APIキー」、説明「TypeSafeのコンソール(console.typesafe.ai)で発行したキー」。
  - 登録したら「TypeSafeのAPIキーを登録しました。メッセージの右クリックメニュー(アプリ)の「Jevに聞く」と `/jev` で使えます。」と知らせる。使えない文字が入っていれば「キーに使えない文字が含まれています。TypeSafeのコンソールでコピーし直して、もう一度登録してください。」。キーが使えないとき、確かめられないとき、登録中のエラーのときは、Anthropicのキーと同じ文を使う。
  - 入力は、Anthropicのキーと同じく、全角の英数字を半角にし、空白と見えない文字を取り除いてから使う。
  - AIのキーとは別の表(`typesafe_credentials`)に保存する。AIのキーの表は、プロバイダの値を制約(CHECK)で決めていて、変えるには表を作り直し、本番のキーを移し替えることになるため。TypeSafeのキーは、AIの呼び出しにも寄付にも使わない。
- **GitHub(エージェント):** エージェントのGitHubとの連携で受け取るトークン(本人に代わって操作するトークンと、更新用のトークン)は、`/setup`ではなく、エージェントの「GitHubと連携」のボタンから連携して受け取る(仕組みは[アーキテクチャ](architecture.md)「エージェント(Bobert Agent)」の「GitHub」を参照)。GitHubのトークンにはLLMの費用がかからないので、寄付とは関係しない。
- **有効性の確認:** 登録時に、料金のかからないAPI(Anthropicのモデル一覧API)を呼び、キーが有効か確かめる。OpenRouterのキーは、OpenRouterから受け取ったものをそのまま使う。TypeSafeのキーは、料金のかからないモデル一覧のAPI(`GET https://api.typesafe.ai/v1/models`)で確かめる。
- **保存:** Workerのシークレットにある鍵で暗号化して(AES-256-GCM)、D1に保存する。ログには出さない。GitHubのトークンも、同じ鍵で暗号化して保存する。
  - 暗号文は持ち主(ユーザーIDとプロバイダ)に結び付ける。ほかの人の行に移しても復号できない。
- **暗号鍵の入れ替え:** 暗号化したデータに鍵の番号を付けて、鍵を入れ替えられるようにする。
- **バックアップ:** D1標準の復元機能(Time Travel)に任せる。過去30日の任意の時点に戻せて、追加料金はかからない。
- **削除:** 本人がスラッシュコマンド(`/delete`)で、いつでも削除できる。確認のボタンを押すと、キーと設定を消す(TypeSafeのキーも消す)。キーがなくなるので、寄付も消す。自動では削除しない。キーや設定は個人に紐づくので、Botがサーバーから外されても残す。OpenRouterで発行されたキーは、OpenRouterのサイトでも削除できることを案内する。
  - 記録を消した後に、エージェントのチャンネルとセッション、作っている途中の動画のセッションを、sigwを通して消す(費用は本人に付く)。本人のために作った環境とvaultは削除し、エージェントの設定はアーカイブする(削除できないため)。
  - GitHubと連携していれば、連携の記録を消し、GitHubへの承認も取り消す。確認の文に「GitHubとの連携も外します。」を足す。
  - 記憶も、すべてのサーバーの分を消す。記憶を使ったことがある人には、確認の文に「記憶も、すべてのサーバーの分を消します。」を足す。

## ユーザーごとの設定

- 各ユーザーが自分の設定(使うモデル、AIへの自分用の指示など)を持つ。AIへの指示については[Botの振る舞い](behavior.md)を参照。
- モデルは、スラッシュコマンドで送るセレクトメニューから選んで変更する。
- 既定のモデルはClaude Haiku 5.5。
- 思考の深さ(effort)の既定は`low`。モデルが`low`を選べなければ、いちばん近い段階を使う。近さが同じなら浅い方にし、`none`(考えない)は、ほかに選べる段階がないときだけ使う。
- ユーザーごとの設定を変更するためのメッセージは、本人にしか見えないメッセージ(エフェメラル)で送る。

  - 学習に使わないプロバイダでは使えないモデルの場合は、使うときにエラーで知らせる。
  - 画像とPDFを読めるかは、Claudeは読めるものとし、それ以外はOpenRouterのモデル情報(入力の種類)で判断する。モデル情報(モデル一覧)は、取得したら1時間使い回す。
- **`/effort`の選択肢:** モデルごとに選べる段階が違うので、OpenRouterのモデル情報(対応する段階)から作る。
  - Claudeは`low`〜`max`。
  - 「その他」で入力したClaudeは、sigwを通して、Anthropicのモデル情報から作る。古いモデルには、選べない段階があるため。このモデル情報も、取得したら1時間使い回す。
  - 既定の段階に「(既定)」を付ける。モデルが`low`を選べなければ、代わりに使う段階に付ける。既定の段階を選ぶと、設定を消して既定に従う(モデルを変えても、そのモデルで代わりに使う段階になる)。
  - 返答のたびに、使うモデルでその段階を選べるか確かめ、選べなければ、いちばん近い段階を送る。
  - モデルを変えたときに、保存した段階を新しいモデルで選べなければ、既定に戻す。
- **Web検索の費用:** 1回の返答での検索は5回までにする。利用量の表示の費用には、検索の費用も含める。
  - OpenRouter経由: 1回あたり約$0.005〜0.014と、検索結果のトークン分。
  - Anthropicで直接呼ぶ場合: 1,000回あたり$10。
- **一覧の管理:** 候補の一覧は設定ファイルで管理し、定期的に見直す。モデルの入れ替わりが速いため。

## クレジットの寄付

ユーザーは、指定した額のクレジットを、サーバーの全員が使えるように寄付できる。寄付された分は、寄付した人のキーで答える。

いまは、寄付を返答に使わない。返答の費用は、頼んだ人がsigwを通して払う(「AIの呼び出しと費用の負担」を参照)。寄付の仕組みは、別に外す。下は、寄付を使っていたときの決まり。
- **寄付のしかた:** `/donate`で、寄付、残りの確認、寄付をやめる操作をする(画面と文言は[Botの振る舞い](behavior.md)を参照)。寄付はサーバーごと。
  - 1回の寄付は$1〜$100で、小数点以下2桁まで。打ち間違いで大きな額を寄付しないよう、上限を付ける。何度でも足せる。
  - 寄付するには、キーの登録が必要。
  - 寄付をやめると、残りは使われない。やめた後に寄付し直したら、その額から数え直す。
- **使う順番:** 寄付があれば、キーのない人も使える。キーを登録している人の返答にも、先に寄付を使う。寄付が複数あれば、古い順に使う。
  - 寄付した本人の返答には、本人の寄付は使わない。同じキーなので、寄付が減るだけのため。
- **モデル:** 使う人の設定のモデルで答える。キーのない人は、既定のモデル(Claude Haiku 5.5)で答える。
  - 寄付した人のキーで呼べないモデルには使わず、本人のキーで答える。例えば、Anthropicのキーだけの人の寄付では、GPTやGeminiは呼べない。
  - 「その他」で入力したモデルには使わない。費用が分からないことがあり、単価に上限もないため。
- **対象:** メンションへの返答、「Bobertに聞く」、要約(自動と今すぐ)。記憶をまとめるときと、知識チャンネルのファイルを要約するときには使わない(「記憶の費用」と「知識チャンネルの費用」を参照)。
- **差し引き:** APIを呼ぶたびに、その分の費用を寄付から差し引く。
  - 費用は、利用量の表示と同じ計算で出す。それでも分からない回(単価を取得できなかったときなど)は、候補の一覧の単価で見積もる。
  - 費用は呼んだ後に分かるので、使い切る直前の返答の分だけ、寄付した額を少し超えることがある。同時にいくつか返答していると、超える分が増える。超えた分は、次に寄付したときの額から引かない。
- **チャンネル:** 寄付した人がサーバーにいれば、どのチャンネルでも使う。寄付した人が見られないチャンネルの会話も、寄付した人のアカウントに送られる。
  - 寄付を使う前に、寄付した人がサーバーにいるかをDiscordに問い合わせる。抜けていたら(アカウントを消していたら)、その寄付を終える。確かめられなかったとき(Discordの障害など)は、その返答では使わない。
- **キーが使えないとき:** 寄付した人のキーが無効か残高不足なら、その寄付を1時間止めて、次の寄付か本人のキーで答え直す。1時間たつか、寄付した人が寄付を足すと、また使う。
- **上限:** 1人あたりの上限は付けない。寄付した人は、残りを見て、いつでも寄付をやめられる。
- **削除:** `/delete`でキーを消すと、その人の寄付も消す。
- **規約(2026-10-28時点):** AnthropicもOpenRouterも、クレジットを他人に譲ることや売ることを禁じている。Anthropicは「クレジットは、アカウントの持ち主だけが使える」としている。
  - 寄付では、クレジットは寄付した人のアカウントに残り、Bobertは寄付した人のキーで呼ぶ。このため、譲渡ではなく、持ち主の利用と考える。
  - ただし、ほかの人への返答に使うことを、はっきり認めた記述はない。
  - キーでの利用は、すべてキーの持ち主の責任になる(OpenRouterの規約3.2)。
- **会話の扱い:** 寄付で答えた会話は、寄付した人のプロバイダに送られる。OpenRouterで入力と出力の記録(Input & Output Logging)をONにした人が寄付すると、寄付で答えた会話を、その人が読める。
  - 寄付するときの説明に、このことと、費用が概算であることを書く。

## 記憶の費用

記憶([アーキテクチャ](architecture.md)「記憶」を参照)をまとめる費用は、本人のアカウントにかかる。本人がその場で頼んでいないのにLLMを呼ぶのは、Bobertではこれが初めて。Web検索と同じく、費用が増える機能なので、既定はOFFにする。
- **まとめる費用:** 最初の一覧と、1日1回までの更新。sigwを通して、本人の費用で、Claude Haiku 5.5を呼ぶ。寄付は使わない。キーの登録は要らない。
  - 目安: よく話す人の1日分の更新で約$0.0015(入力1万トークン、出力1,000トークンと仮定)。毎日更新しても、月5セントほど。最初の一覧は、保存しているすべての発言を読むので、発言5,000件ごとに約$0.03かかる(2,000件なら約$0.01〜0.02)。`/memory`の画面の費用の注記には、この目安を書く。
  - 1回に渡す発言は6万文字までにする。Haiku 5.5の単価は、入力が10万トークンを超えると約5倍になるため。
  - Bobertを使わない日は、更新しないので、費用がかからない。
- **返答の費用:** 返答に記憶を入れると、入力が増える(一覧は1500文字までで、約1,000〜2,000トークン)。プロンプトキャッシュが効くので、2回目からは、その分の料金は通常の1割ほど(Opus 5.5は5%)。この分は、その返答の費用を払う人(本人か、寄付した人)の負担。
- **寄付で答えるとき:** 記憶も、会話と同じく、寄付した人のアカウント(AnthropicかOpenRouter)に送られる。このことは、`/memory`の画面で本人に伝える。

## 知識チャンネルの費用

知識チャンネル([アーキテクチャ](architecture.md)「知識チャンネル」を参照)の費用は、次のように分ける。記憶と同じく、本人がその場で頼んでいないのにAIを呼ぶので、要約の費用は、ファイルを送った人にかける。
- **要約:** sigwを通して、ファイルを送った人の費用で呼ぶ。Claude Haiku 5.5で、渡すのは文字にした内容の先頭の6万文字まで。入力の10万トークンを超えないので、1ファイルあたり多くても約1セント。
  - 寄付は使わない。キーの登録は要らない。Bobertにsigwのキーがないときだけ、ファイルを受け付けない。
  - 要約できたファイルは保存して使い回すので、同じファイルの要約は1回だけ。
- **一覧と、読んだファイル:** その返答の費用を払う人(本人か、寄付した人)の負担。
  - 一覧の分だけ、毎回の入力が増える(50件で1万トークンほど。Haiku 5.5なら1回約$0.001で、キャッシュが効けば、その1割)。
  - ファイルを読めば、読んだ分(1回で5万文字まで)も増える。
- **運営者の負担:**
  - 文字にする費用(Workers AIのMarkdown変換): Cloudflareの説明では、多くの形式の変換は無料。画像の変換はAIのモデルを使うので、無料枠を超えると費用がかかることがある。PDFとWordに埋め込まれた画像は、変換しない設定にしている。
  - PowerPointをPDFにするコンテナ(Cloudflare Containersの`standard-1`。メモリ4GiB、vCPU 1/2、ディスク8GB): 動いている間だけ課金され、最後に使ってから1分で止める。1回の変換で、動き出す時間と、止まるまでの1分を合わせて約1.5分動くとすると、メモリは0.1GiB時間。Workersの有料プランには、毎月、メモリ25GiB時間、vCPU 375分、ディスク200GB時間が含まれるので、月250回ほどまでは、含まれる分で収まる(続けて送られたファイルは、止まる前に変換するので、もっと少なく済む)。超えた分は、1回約0.1セント(メモリ1GiB秒あたり$0.0000025)。
  - R2: PowerPointをPDFにしたものの保存。毎月10GBまでの保存と、100万回までの書き込みが無料で、消すのは無料。
  - 中を探すためのベクトル: ファイルの先頭から1,000文字ごとに1つ、1ファイル300個まで。埋め込み(bge-m3)は、30万文字でも約$0.004(メッセージの埋め込みと同じ単価。1日ごとの無料枠もある)。Vectorizeの保存と検索の費用は、メッセージのベクトルと同じ計算で、件数が増える分だけ少し増える([アーキテクチャ](architecture.md)「保存と検索の費用」を参照)。
  - D1: 文字にした内容と、要約の保存。含まれる量の範囲内の見込み。
- **送る内容:** 要約のために、ファイルの中身(先頭の6万文字まで)を、sigwを通してプロバイダに送る。返答で一覧やファイルの中身を使うときも、会話と同じく、sigwを通して送る。PDF、Word、Excelのファイルは、文字にするためにCloudflareのWorkers AIに送る。PowerPointは、Cloudflareの中で動かすコンテナでPDFにする(Cloudflareの外には出さない)。

## エージェントの費用

`/agent`のエージェント(Claude Managed Agents。[アーキテクチャ](architecture.md)「エージェント(Bobert Agent)」を参照)も、返答と同じくsigwを通して呼ぶ(#126)。費用は、エージェントのチャンネルの持ち主(セッションを始めた人)が払う。運営者は負担しない。
- **通り道:** エージェントの設定、環境、セッション、イベント(流れ、一覧、送信)、セッションの資源、ファイル、vaultのAPIを、すべてsigwの中継(`https://sigw/anthropic/v1/...`)で呼ぶ。中身は変えずに中継され、SDKが付ける`anthropic-beta`ヘッダーもそのまま届く。呼び出しのたびに、チャンネルの持ち主のDiscordのIDを`x-sigw-user`で送る。
- **かかるもの:** トークン代(通常のAPIと同じ単価)と、セッションが動いている(`running`)間の1時間あたり$0.08。待っている(`idle`)間は数えない。コンテナの料金は別にかからない。Web検索を使えば、その料金もかかる。
  - セッションの料金は、セッションを作る応答やイベントの送信の応答には出てこない。sigwは、セッションを作る呼び出し(`POST /v1/sessions`)を中継したときに、そのセッションと`x-sigw-user`の人を記録し、定期的に(と、セッションを消す直前に)セッションの使用量の累計を読んで、増えた分(トークン代と実行時間の料金)をその人に付ける(4rtofl/si-gateway#7)。
- **使える人:** 誰でも使える(本人のキーの登録は要らない)。Bobertに、Anthropic用のsigwのキー(`SIGW_ANTHROPIC_KEY`)が要る。Managed AgentsはAnthropicのAPIの機能なので、OpenRouterのキーだけでは使えない。sigwのキーがないときは、「いまはAIを呼び出せません。Bobertの管理者に知らせてください。」(返答と同じ文)と知らせる。
- **寄付は関係しない:** 費用はsigwが本人に付けるので、寄付は使わない。
- **上限:** Bot側では付けない。今の方針(Bot側では使用量の上限を設けない)に合わせる。Managed Agentsの、セッションごとの上限額の機能も使わない。上限額は、sigwのキーに設定できる。
- **記録:** セッション、ファイル、vaultは、sigwのキーのワークスペース(Bobert専用のワークスペース)に作られる。セッションの記録(会話と作業の内容)は、消すまでそこに残る(ゼロデータ保持の対象外)。ワークスペースの持ち主(sigwのキーの持ち主)は、Claude Consoleで読める。本人は読めない。持ち主が読めることは、Bobertを使う3人で受け入れた(2026-11-22)。セッションを終えると消す。
  - 本人のアカウントで作っていたもの(#126より前のセッション、環境、vault)は、Bobertからは見えなくなる。続きの操作はできないので、新しく作り直す。本人のアカウントに残ったものは、本人がClaude Consoleで消せる。
- **スキル:** サーバーのスキルの一覧と、Anthropicの文書のスキルの説明の分、セッションの入力が少し増える。スキルを読めば、本文の分も増える。どちらも本人の負担。
- **ファイル:** 本人が添付したファイルは、Bobertのワークスペースのファイル(Files API)に上げてからサンドボックスに置く。上げた元のファイルは、置いた後に消す。サンドボックスに置いた写しと、エージェントが作ったファイルは、セッションと一緒に消える。
- **運営者の費用:** チャンネルごとのDurable Objectは、エージェントが動いている間だけイベントの流れを受けるので、待っている間のセッションは、運営者の費用を増やさない。

## 動画の作成の費用

動画の作成([アーキテクチャ](architecture.md)「動画の作成」を参照)の費用は、2つに分かれる。どちらもsigwを通し、動画を頼んだ人が払う。寄付は関係しない。
- **台本を書くAI:** 今の返答と同じく、返答を頼んだ人(動画を頼んだ人)の負担。会話と、発言に貼られたURLの先のページ(1回の返答で10件、1ページ10,000文字まで)を読む分、入力が増える。
- **動画を作るサンドボックス:** エージェントと同じく、Managed AgentsのAPIをsigwを通して呼び、動画を頼んだ人のDiscordのIDを`x-sigw-user`で送る(#126)。運営者は負担しない。
  - かかるのは、セッションが動いている間の1時間あたり$0.08と、コマンドを実行させるClaude Haiku 5.5のトークン代。sigwが、エージェントと同じ仕組みで記録する。試作では、全体で約2分、1本あたり約$0.004だった(VOICEVOX ENGINEのダウンロード(約2GB)に約1分かかる。毎回ダウンロードする)。
  - 誰でも使える(本人のキーの登録は要らない)。Bobertに、Anthropic用のsigwのキーが要る。
  - 上限はBot側では付けない(エージェントと同じ)。上限額は、sigwのキーに設定できる。
  - 台本のファイルは、Bobertのワークスペースのファイル(Files API)に上げてからサンドボックスに置く。動画を投稿したら(失敗したときも)、セッションと、上げたファイル、出したファイルを消す。それまでの記録は、エージェントと同じく、ワークスペースの持ち主がClaude Consoleで読める。
- **運営者の費用:** 利用者ごとのDurable Objectが、作っている間だけ30秒ごとのアラームで動く(1本あたり数回〜30回)。有料プランに含まれる量の範囲内の見込み。

## Jevの費用

右クリックメニューの「Jevに聞く」と`/jev`([Botの振る舞い](behavior.md)を参照)では、AIが作った質問を、TypeSafeの判定モデルJevに聞く。Jevの費用は、使った本人のTypeSafeのアカウントにかかる。運営者は負担しない。
- **単価:** 入力100万トークンあたり$0.042で、出力は無料(2026-11-04時点、TypeSafeの資料)。1回の質問は数百〜数千トークンなので、$0.0001ほど。
- **AIの費用:** 質問を作るAIの費用は、メンションへの返答と同じく、本人(サーバーに寄付があれば、寄付した人)のAIのキーにかかる。
- **寄付は使わない:** 寄付は、寄付した人のAIのキー(AnthropicかOpenRouter)で答える仕組みで、TypeSafeのキーは寄付の対象ではない。このため、Jevは、寄付で答えるときも本人のTypeSafeのキーで呼ぶ。
- **利用量の表示:** Jevの分は入れない。TypeSafeのアカウントは、AIの費用を払うアカウントと別のため。
- **送る内容:** 対象のメッセージ(発言者の名前と本文)と、AIがまとめたメッセージの意味と文脈を、TypeSafeに送る。TypeSafeは、APIで受け取った入力を学習に使わないとしている(2026-11-04時点のプライバシーポリシー)。
- **OpenRouter経由にしない理由:** JevはOpenRouterでも同じ単価で呼べるが、各自がTypeSafeのキーを登録して直接呼ぶ形にした(2026-11-04、ユーザーの判断)。

## 音声メッセージの費用

音声メッセージを文字にする費用(Workers AIのWhisper。[アーキテクチャ](architecture.md)「音声メッセージ」を参照)は、運営者のCloudflareのアカウントにかかる。埋め込みと同じく、運営者が負担する例外にする(2026-11-05、[issue #91](https://github.com/4rtoflow/Bobert/issues/91)で決定)。
- **単価:** `@cf/openai/whisper-large-v3-turbo`は、音声1分あたり46.63ニューロン(約$0.0005)。1,000分で約$0.51(2026-10時点のCloudflareの資料)。
- **無料枠:** Workers AIは、1日1万ニューロンまで無料(UTCの0時に戻る)。この音声認識だけなら約214分にあたる。無料枠は、検索用の埋め込みと共用。
- **かかる場面:**
  - 共有チャンネルに届いた音声メッセージは、前もって文字にするので、Bobertに話しかけていない音声メッセージの分もかかる。
  - 前もって文字にしていないもの(この仕組みを入れる前のものや、年齢制限のチャンネルと非公開スレッドのもの)は、返答の中で必要になったときにかかる。1回の返答で新しく文字にするのは、合わせて20分まで。
  - 文字にした内容は保存して使い回すので、同じ音声メッセージの分は、1回だけかかる。
  - エージェントのチャンネルの音声メッセージも、運営者が負担する(エージェントの費用は本人の負担だが、文字にするのはBobertの側のため)。
- **かからない場面:** キーも使える寄付もない人の音声メッセージには、返答しないので、文字にもしない。
- **AIの費用:** 文字にした内容は、ほかの発言と同じく会話に入るので、その分の入力の費用は、返答の費用を払う人(本人か、寄付した人)の負担。
- **送る内容:** 音声は、CloudflareのWorkers AIに送る。Cloudflareは、このモデルを、送ったデータを保存しない(ゼロデータ保持)ものとしている(2026-10時点のモデルの一覧)。

## 採用しない方式と理由

| 方式                                    | 理由                                                                                                                                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Free/Pro/Maxのサブスクログイン   | Anthropicは、第三者のアプリがClaude.aiログインを提供することと、ユーザーに代わってサブスクの資格情報でリクエストを送ることを禁止している。資格情報やセッショントークンの収集・保存・仲介も禁止 |
| ChatGPTのサブスク(Sign in with ChatGPT) | サーバーでホストするアプリは申請制で、現在は選ばれた商用パートナーのみ                                                                                                                         |
| Google AI Pro/Ultraのサブスク           | Gemini CLIの個人ログインは2026-06-18に終了した。Antigravityの規約は、第三者のツールからのOAuth利用を違反としている                                                                             |
| GitHub Copilotのサブスク(Copilot SDK)   | 公式には可能(パブリックプレビュー)だが、サブスク枠は使わない方針のため                                                                                                                         |
| OpenAI APIキーの直接登録                | 契約の禁止事項に「APIキーを第三者と売買・譲渡すること」があり、グレー。OpenAIのモデルはOpenRouter経由で使う                                                                                    |
| Gemini APIキーの直接登録                | Googleの共通API規約は、資格情報を他のアプリに使わせないよう求めており、グレー。Gemini APIには18歳以上という条件もある。GeminiのモデルはOpenRouter経由で使う                                    |
